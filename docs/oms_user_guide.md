# Order Management System (OMS) User Guide

## Overview

The OMS provides a complete order management pipeline for equity trading with professional-grade portfolio tracking, position sizing, order execution, and audit logging.

## Architecture

```
Strategy Signal
    ↓
OMS.process_signal()
    ↓
Portfolio Constraint Check
    ↓
Position Sizing (Dynamic Rules)
    ↓
Order Creation & Logging
    ↓
Broker Execution (Simulated)
    ↓
Fill Processing
    ↓
Portfolio Update & Ledger Recording
```

## Quick Start

### 1. Initialize Components

```python
from quant_strategies.execution import (
    Portfolio, Ledger, BrokerAgent, PositionSizer, OrderManagementSystem
)

# Create components
portfolio = Portfolio(initial_cash=100000.0)
ledger = Ledger(db_path="data/trading_ledger.db")
broker = BrokerAgent()
sizer = PositionSizer()

# Create OMS
oms = OrderManagementSystem(portfolio, ledger, broker, sizer)
```

### 2. Generate Trading Signals

```python
from quant_strategies.strategies import BollingerRSIStrategy
from quant_strategies.strategies.base_strategy import SignalType

# Create strategy
strategy = BollingerRSIStrategy()

# Generate signal
signal = strategy.emit_signal('AAPL', SignalType.BUY, strength=0.85)
```

### 3. Process Signal Through OMS

```python
# Prepare market data
market_data = {
    'ticker': 'AAPL',
    'last': 150.00,
    'bid': 149.85,
    'ask': 150.15,
    'close': 150.00
}

# Process signal
order = oms.process_signal(signal, market_data)

if order and order.status == OrderStatus.FILLED:
    print(f"Order filled: {order.quantity} shares @ ${order.filled_price}")
```

### 4. Monitor Portfolio

```python
# Get current prices
current_prices = {
    'AAPL': 152.00,
    'MSFT': 355.00,
    # ... other positions
}

# Print portfolio summary
oms.print_portfolio_summary(current_prices)

# Get portfolio metrics
summary = portfolio.get_portfolio_summary(current_prices)
print(f"Total P&L: ${summary['total_pnl']:,.2f}")
print(f"Return: {summary['total_return_pct']:.2f}%")
```

### 5. Query Audit Trail

```python
# Get recent signals
signals = ledger.get_all_signals(limit=10)

# Get order history
order_history = ledger.get_order_history(order.order_id)

# Get fills
fills = ledger.get_fills_for_order(order.order_id)
```

## Position Sizing Rules

The OMS uses dynamic position sizing based on portfolio state:

### Rule 1: First Position (0 positions)
- **Size:** 10% of total cash
- **Example:** $100,000 → $10,000 position

### Rule 2: Active Trading (1-7 positions)
- **Size:** 10% of remaining cash
- **Example:** $70,000 remaining → $7,000 position

### Rule 3: High Position Count (7+ positions)
- **Size:** Maintains 20% cash buffer
- **Logic:** Size to keep 20% of total portfolio value in cash
- **Example:** With 7 positions, reduces new position size to preserve buffer

### Rule 4: No Doubling Down
- **Constraint:** Maximum 1 position per ticker
- **Behavior:** BUY signals rejected if position already exists

## Portfolio Constraints

The OMS enforces several safety constraints:

1. **Single Position per Ticker:** Cannot open multiple positions in same security
2. **Cash Requirements:** Must have sufficient cash for buy orders
3. **Share Requirements:** Must have sufficient shares for sell orders
4. **Minimum Quantity:** Orders with 0 quantity are rejected

## Order Lifecycle

### States
- **PENDING:** Order created, not yet submitted
- **SUBMITTED:** Order sent to broker
- **PARTIAL_FILL:** Partially filled (future enhancement)
- **FILLED:** Completely filled
- **CANCELLED:** Order cancelled (future enhancement)
- **REJECTED:** Order rejected by broker or OMS

### Complete Flow
1. Signal generated by strategy
2. Signal recorded to ledger (append-only)
3. Position size calculated
4. Portfolio constraints checked
5. Order created and recorded (PENDING)
6. Order submitted to broker (SUBMITTED)
7. Broker executes order
8. Fills received and recorded
9. Portfolio updated with new position
10. Order status updated (FILLED)
11. Position snapshot recorded

## Ledger System

The ledger provides an append-only audit trail:

### Tables
- **signals:** All trading signals generated
- **orders:** Complete order history (each status change = new row)
- **fills:** All order executions
- **position_history:** Position snapshots over time

### Benefits
- Complete audit trail
- Never lose historical data
- Can reconstruct portfolio state at any point in time
- Regulatory compliance ready

## Error Handling

The OMS logs all errors and rejections:

```python
order = oms.process_signal(signal, market_data)

if order is None:
    # Signal rejected (e.g., duplicate position, no cash)
    print("Signal rejected - check logs")
elif order.status == OrderStatus.REJECTED:
    # Order rejected by broker
    print("Order rejected - check market data")
elif order.status == OrderStatus.FILLED:
    # Success!
    print("Order filled successfully")
```

## Best Practices

1. **Always Check Order Status:** Verify orders filled before proceeding
2. **Update Prices Regularly:** Keep portfolio valuations current
3. **Monitor Cash Buffer:** Ensure sufficient cash for operations
4. **Review Ledger:** Regularly audit trading activity
5. **Handle Rejections:** Implement proper error handling
